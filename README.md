# CS-255-System-Analysis-and-Design
A repository for my CS-255 class at SNHU.

The projects for this course had me design a system for a fictional company DriverPass. DriverPass' goal was to provide improved driving training to help customers pass their driving tests at the DMV. In order to accomplish this goal, I designed a system that allows customers to take online practice tests, online courses, and schedule in-person driving lessons. The system also allows for customers to have an in-person or over the phone meeting with the DriverPass secretary, to set up their account and make reservations to schedule in-person driving lessons. The DriverPass system accounts for various user roles and levels of access, allowing Admin roles to print or download activity reports. 

In my opinion, I excelled at the Class Diagram and thinking about various objects in the system. My experience using Object Oriented Programming helped tremendously with this. If I could choose one of my diagrams to revise it would be the Use Case Diagram that showed the various actors and how they interact with the various use cases. I found this diagram to be confusing, and difficult to link actors to use cases properly. 

My methodology for designing a system ties greatly into interpreting the user's needs. I went through the interview transcript multiple times, making many lists of requirements for different parts of the system. These lists were a huge help in ensuring my design includes all of the user needs. It is crucial to consider the user's needs when designing a system, otherwise, you run the risk of designing a system that is not needed or wanted. When designing a system you are required to meet these needs so considering them careful is of vital importance. As implied, I am a huge fan of lists. They are easy to refer back to and can be indented to show subsystems. So, making detailed lists and paying attention to the requirments of the client are how I will continue to design systems in the future.
